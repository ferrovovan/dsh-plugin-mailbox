# CHANGELOG

## 0.1.4 — 2026-11-05
- `mailbox_throttle action=target` — сессия-получатель изнутри (право
  адресата), с проверкой по живому реестру перед сохранением;
  `mailbox_status` показывает цель.
- Закрыт по живому факту: ключом `agents.get` является id сессии
  (typert-resolver: resolve(sessionId => get(sessionId)); живой вызов
  throttle в своей сессии — подтверждение, что ctx.agents вообще тут).

## 0.1.3 — 2026-11-05
- Слово Мастера: рубильник строки ВКЛ (cordis.patch.yml бандла).
- Пустой `targetSession`: если живая сессия ровно одна — получатель она;
  при нескольких — честный пропуск с причиной (не угадываем).

## 0.1.2 — 2026-11-05 (живая приёмка после рестарта)
- Тулы зарегистрированы живым харнессом и вызываются: `mailbox_status`
  работает (рубилен false → «ПАУЗА»), — регистрация с output подтверждена
  вживую.
- Фикс по живому факту: харнесс валидирует ВЫВОД вызова по output.schema
  (`additionalProperties:false`) — throttle возвращал полный снимок и
  живой вызов падал («deliveredThisHour is not a declared property»).
  Отдаём ровно объявленные поля; офлайн-тест теперь гоняет живые
  валидаторы и на значения вывода.

## 0.1.1 — 2026-11-05
- Фикс парсера писем: регулярка не ловила кириллические имена полей в
  нижнем регистре («Тема», «Статус»…) — на живом формате Mailbox/
  (plain `Тема: …`) НЕ расшивалось ни одно поле (замер офлайн).
- Контракт тулов: `mailbox_status`/`mailbox_throttle` несут обязательный
  `output {schema, render}` (харнесс 0.2.2-alpha.2: без него register
  бросает TypeError); отказ регистрации — громкий.
- `agent.inject` получает полноценный UserMessage (id uuid, role,
  content-блоки, source.kind=dsh-mailbox) — по dsh-llm createUserMessage.
- Пауза/лимит: попытка сохранения в конфиг строки через configEditor;
  при отказе — честная строка `persisted` в ответе тула.
- README: где взять targetSession.
- Офлайн-прогон живым fs.watch: пауза→0, resume→доставка, закрытое→минус,
  лимит 2→3-е отклонено с причиной (цифры в INTERNAL.md).

## 0.1.0 — 2026-11-05
- Заготовка: слежение ящика, почасовой порог, пауза/возобновление
  (`mailbox_throttle`, `mailbox_status`), доставка-заметка в targetSession,
  документация и проверки.
